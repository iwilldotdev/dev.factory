# LESSONS: what v0 taught us, one row per incident

Purpose: record every concrete failure observed while running dev.factory v0 (CHANGELOG, DESIGN, five handoffs, the provider-agnostic design notes) so the v1 rewrite ports the learning, not the code.

How v1 uses it: every v1 feature cites an `L-nn` from this file or a real ticket need. A feature with neither does not enter. Every `test` row becomes a v1 test that fails without the rule. `by-design` rows need no code: the new design removes the failure class. Owner decision at M0: the alpha keeps every v0 capability, so no row is deferred (the former `out-of-alpha` rows were redesigned; see `docs/parity-map.md`).

Origin shorthand: `CL` = v0 CHANGELOG entry (the Unreleased section is cited by title); `DS §n` = v0 DESIGN section; `H1` = Handoffs/2026-11-13-falhas-observadas-lote-escopos (item #); `H2` = Handoffs/2026-11-23-analise-runs; `H3` = Handoffs/2026-11-24-pendencias-pos-agnosticidade; `H4` = Handoffs/DEV-9531-sessao-principal (item #); `H5` = Handoffs/DEV-9593-sessao-principal; `PA` = docs/design/provider-agnostic.md and docs/research/2026-11-23-providers-e-instalacao-unificada.md; `run NNNN` = a real run.

Neutral vocabulary is deliberate: tracker, SCM, change request, design source, MCP server.

### The ten lessons that matter most for the alpha design

1. L-17 / L-109 to L-115: regex and grammar write guards are bypassable by construction (six audit rounds, hundreds of probes); v1 trusts evidence bound to spec hash, SHA and clean worktree, and keeps hooks optional.
2. L-01, L-08, L-09, L-10: only `verify` writes evidence, a gate needs a `pass` at the current HEAD with the locked spec hash, and the same SHA plus spec hash is never re-run.
3. L-02 to L-05: setup failure, zero tests and a loose failure pattern must never count as a pass or a reproduction.
4. L-131, L-132, L-136: lock the plan, the check files and the effective config caps; every change goes through `plan amend` with a counted loop or a recorded user decision.
5. L-27, L-28, L-33 to L-35: a bug needs a reproduction on the base that uses the ticket's own scenario and media, and red-green must test committed files, not run-folder copies.
6. L-69, L-71, L-72, L-64: runtime evidence must prove which code the env served (path and SHA), from the run's worktree, with its own dependencies and `.env`.
7. L-42, L-43, L-44, L-46, L-168: every check has a cap that kills the process tree, stdin is always closed, and env-kind failures stop the batch and block `next` after two repeats.
8. L-21, L-121, L-155: remote facts used as proof need `source: adapter` (or a recorded user confirmation); agent-written contracts are fine for ticket text only.
9. L-164, L-165, L-15: append-only `events.jsonl` removes lost-write, overwritten-evidence and concurrent-writer failures at once.
10. L-173, L-148, L-44: the suite budget (parallel, temp dirs, fixture repos copied) and the cwd/PYTHONPATH/stdin rules are what made v0 slow and fragile on Windows.
