# Changelog

## Unreleased

- fix: safe target switching for hotfix envs (second review of the mirror runtime). The pid record gains `run` (id of the run that started the env; old records lack it and are never taken as a run's own outside its worktrees). A hotfix run restarts or stops an env of another target only when it is served from the run's own worktree or the record's `run` is this run, so with `env.lease` off it no longer takes over an env another run or a manual `env up` started from the main checkout (`env serves ... (run none)` as before the mirror work). `prove` preflight restarts stale envs in `depends_on` order, dependencies first (it relied on `aliases` being dependents first, but it is alphabetical; this also restores the order of non-hotfix runs). `env check --auto-restart --target` restarts the run's stale dependencies first. `env down --target` leaves a dependency another run started (`left running (run <id>)`). Tests: `tests/test_env_mirror_target.py`.

- `factory run target-ticket <run> <target> <KEY>`: in a hotfix run with several tickets, the MR of that target is titled with that ticket (`hotfix.tickets[target]`, `target_ticket` event); without it every MR keeps the first ticket. The worker guard now reserves `run target-ticket|env-only|mirror` for the main session. Tests: `tests/test_target_ticket.py`, `claude/hooks/test/worker-guard.test.mjs`.
- Hotfix mirror runtime checks (DESIGN section 9): `factory env up|check <ws> [repo] --run <run> --target <target>` serves a mirror target from its worktree (repos without one keep the run's resolution; a repo's optional `target_paths: {target: dir}` applies, validated by `workspace check`). The target is stored in the env pid record: `env check` reports it and every restart path (`restart_env`, `env check --auto-restart`, `prove` preflight and `--final` restart) keeps it. `factory prove <run> --target <target>` runs only that target's checks (quality and rules only for the base target; `--estimate` honours it), so a mirror env no longer fails the base checks by fail-fast. `env down --run --target <t>` also stops the `depends_on` repos this run started for that target (not those held by another run or started for another one), and a stale mirror env of a hotfix run counts as the run's own for `restart_blocker`, so `prove --target` switches targets (dependencies restart first, including repos served from `target_paths`); `prove --check QUALITY-x|RULE-x --target <mirror>` is a usage error; `workspace check` requires `target_paths` keys to be known mirror targets and values absolute. Without the flags nothing changes, except that the env-binding of dependency repos in a hotfix run now expects the run worktree (what `env up` serves) when no mirror worktree exists. Tests: `tests/test_env_mirror_target.py`.
- env_only repos (from the DEV-9431 hotfix run, where API, Legado and IA were registered only so the env would start from homolog worktrees and `gate build` then demanded commits from them): `factory run branch <run> <repo> --base <b> --env-only` registers a worktree marked `env_only: true`, and `factory run env-only <run> <repo> [--off]` marks or unmarks a repo already registered (any phase, no replan, logged as an `env_only` event). `env up/check/login --run` still use those worktrees. `gate build` (commits, dirty, header/trailers), `gate prove`/`review` (touched repos, quality and rule checks, review head binding), `prove` repo selection, `review record`, feedback shas, `run mirror`, `shots` UI-repo detection and `ship plan`/`verify` skip them (new `core.code_repos`). A dirty env_only worktree blocks nothing. `gate build` fails when every repo is env_only. Tests: `tests/test_env_only.py`.

Fast verification, parallel envs and engineering review (DESIGN §11, §14). Driven by the DEV-7853 epic evaluation (session "[Tarefas | Personalização de campos]"): the 9451 run spent 21.8 h in prove with 762 check executions, passing checks rerun 15–20× at the same sha, a new check failing only after 27 min, React restarted on every HEAD, and test data piling up in the dump. Audited independently twice (opus); the first audit's 2 blockers and 3 majors are fixed with regression tests (`tests/test_verification_audit.py`).

- prove fail fast / pass fast:
  - Risk order: last fail/error first, then new or changed checks, then checks whose repo moved, then the rest; cheapest type first in each group.
  - Evidence reuse: a `pass` at the same repo HEAD, same `details.check_digest` (new `integrity.check_digest`) and, for runtime checks, the same `details.run_heads` of every run repo, is not rerun (`REUSED`). `--all` forces everything. `evidence_error` also treats a changed check digest or changed run heads as stale.
  - Modes: `--bail` (stop at the first runtime assert failure), `--fast` (bail + reuse + `quality_fast`), `--final` (run everything, strict env binding). Evidence records `details.mode`; `gate prove` refuses `mode=fast` and `hot_reload` evidence. A `prove` event records mode, ran/reused/skipped/failed and wall time.
  - Flaky: a browser assert failure is retried once; a pass on retry stays `fail` with `details.flaky` and `PROVE-FAIL kind=flaky` (`--no-retry`).
  - Batched browser checks: browser checks of one repo run in one Playwright process (`run-specs`, one project per check) and are split back into per-check evidence; falls back to one-by-one. Opt out with `limits.browser_batch: false`.
  - `prove --estimate`: expected time per check (REUSED/RUN) and totals, without running anything.
  - Repo `quality_fast` with `{changed}` (files changed since the merge-base), used only in fast mode.
- `factory run amend-check <run> CHK-n --kind timing|selector --reason`: fixes a check's waits/timeouts (and, for selector, its own spec files) without a full replan. Refused when a changed file is read by another check, or when workspace.json changed since the lock; the relock keeps the old workspace digest. A timing amend does not count against `max_replans` with `autonomy.allow_timing_amends`.
- Env:
  - `env.hot_reload` (Vite): a new HEAD does not restart the server in default/fast modes; `--final` restarts it so final evidence comes from a process started at HEAD.
  - `env.seed {cmd, reset}`: `env seed` / `env reset-data --run` (with `FACTORY_DATA_PREFIX=UAT<ticket>`), and prove resets data once before the runtime batch. `env.preflight[]` runs in `env check` (`ENV-FAIL kind=preflight`), e.g. for the trigger the daily dump reset drops.
  - Per-repo leases (`env/<ws>/<alias>[@k]/lease.json`, all-or-nothing in repo order, FIFO across repos), slots (`slots`, `port_stride`, ports/health/base_url/start shifted by `k*stride`, run.json `env_slots`), `shareable` repos with shared leases, `{base_url:ALIAS}`/`{port:ALIAS}` placeholders resolved per slot, `login.handoff_rewrite` (rewrites the legacy → React hand-off URL to the slot port; the React cookie is host-only so it is port-agnostic). Storage/login state is per slot, the pid record carries an `env_digest` of the resolved env, and the legacy `lease.json` holds a marker for older factory versions. Slot math and leases live in `factory/commands/env_lease.py` (re-exported by env.py).
  - prove now checks the env binding of the `depends_on` closure of runtime repos too (and `--final` restarts a stale one it holds), so `run_heads` never claims a dependency HEAD that is not being served (re-audit A3).
  - Without the new keys behaviour is unchanged.
- Engineering quality: authors write `notes/design.md` (Approach, Complexity, Reuse, Architecture risks) for medium/high risk runs; builders follow it; the code auditor now reviews complexity, readability, architecture and reuse ("No formatting nits; readability and design problems are findings") with a finding `category`. Workspace rules with `kind: guideline` go to the auditor.
- Ship: the MR description lists unresolved minor findings in `## Follow-ups`.
- Skill: early UAT checkpoint after the first `gate build` for UI runs (screenshots + assumed decisions from run.json), a scout checks whether a new decision is already met before a builder runs, child sessions recommended for epics of 3+ tickets or more than a day, `prove --estimate` for "how long" answers.
- `factory metrics`: `phase_hours`, prove invocations by mode, check executions/status, slowest and most-rerun checks, flaky count; child runs without transcripts get tokens attributed from the parent's transcripts (or `tokens: null` with a note). `batch status` shows each child's last prove and slots.
- Known limits (audit, minor): reuse of evidence recorded before this change never happens (it has no `check_digest`/`run_heads`), so the first prove after upgrading runs everything; `--estimate` ignores batching and overestimates browser time; one shared-repo caveat — evidence can depend on another run's code in a `shareable` repo (recorded in `details.shared`).

- Style probe (browser `style-probe`) now measures `fontFamily`, `text`, `borderColor` and `borderWidth`, so the `factory figma expect` expectations for them no longer fail as "unknown property". This came from the "[Tarefas | Personalização de campos]" session; it landed in 72ac634 and was audited afterwards.
  - `fontFamily` compares the first family only, unquoted and case-insensitive.
  - `text` compares the trimmed `innerText` exactly.
  - `borderColor` is a normalized color, taken from the first side with width > 0, else the top side.
  - `borderWidth` is in px, with the default tolerance.
  - Fixed after the audit (false PASS):
    - An empty expected `text` now fails, with the note "expected text is empty".
    - An expected `borderWidth` > 0 now fails against 0 px or a missing border, with the note "border missing (0px or style none)". The px tolerance still applies to a border that is present.
  - Known limits (audit, minor, false FAIL only):
    - Multi-line text, and text changed by `text-transform`, fail, because Figma line breaks and case are not normalized.
    - Hashed font names (e.g. next/font `__Inter_abc123`) fail.

- Fixes from the same session (e25991f, ccd2232, 3ddcfaa):
  - `capture` reads the text of non-HTML targets (e.g. `svg`) with `textContent`, since `innerText` exists only on `HTMLElement`.
  - Workspace `limits.expect_timeout_ms` sets the Playwright assertion timeout of browser specs. The collector exports it as `FACTORY_EXPECT_TIMEOUT_MS` and the generated config, single and batched, writes `expect: { timeout }`. It is meant for slow databases such as the remote dump. Without the key, Playwright's default of 5 s stays.
  - `gate build` treats commits of merged MRs as inherited. The shas of `mr-*.json` payloads in state `merged` go into `--not`, so a dependency branch deleted after its merge no longer turns its commits into foreign ones. `inherited_allow` also unwraps `{merge_request: {...}}` payloads.

Fail fast and recovery (DESIGN §13), driven by the findings of real runs since 13/11 (Handoffs/ and run transcripts):

- prove: per-check wall-clock caps (`timeout_s`, `limits.check_timeout_s`, 120 s UI / 60 s api) kill the process tree. An env-kind failure skips the repo's remaining runtime checks and exits 3. Two identical failures stop the batch. New `PROVE-FAIL`/`ENV-FAIL` lines. A stale env is restarted once. prove no longer overwrites run.json (`run_update`). `--check` accepts `QUALITY-*` and `RULE-*`.
- Browser CLI: `--timeout-ms`, `--goto-timeout-ms` (30 s) and `--wait-until` (`load`), so there are no more 360 s test or 180 s networkidle waits.
- env check is a preflight: repo and run come from the cwd, a status below 500 is healthy (redirects are not followed), exit codes 0/1/2/3/4, `--auto-restart`. HTTP.sys (PID 4) is judged by health. The lease heartbeat runs before every check, a live holder pid keeps the lease, and `lease release` stops the run's envs. Factory only kills processes whose create time matches its own record.
- Workers: a blocked contract (one self-repair, then `status: blocked` with `infra_signal`, `first_seen_at`, `tried`), enforced by the new `failfast.js` hook on author, builder and auditor. `factory wait` replaces `sleep`, which workers cannot use. Guards allow read-only commands and scripts on run files. `runs/_inbox/**` is writable by scouts. At plan, new browser and api checks get a dry run. The orchestrator runs `env check` before delegating.
- Gates and runs: `review fix` records the MR head and `gate build` checks only later commits, with inherited commits limited to known branches. New `run verify-human` for user-confirmed human checks; pending human checks do not count as review loops. A checks-only replan keeps the code review. Generated files under `checks/` are left out of the plan lock, and adapter files are locked. New `run close` (phase `closed`), `run list --all`, `run retype`, a bug type derived from the Jira issuetype, hotfix mirror branch names that cannot collide, blocker kind `decision`, `workspace list|show`, and `orchestration.max_parallel`. `repo_path_for_env` warns when it falls back to the main checkout.
- Collectors: dotnet output is forced to English. A test or red-green check that runs zero tests fails as `setup`.
- Ship: the MR title is `[KEY] - summary` (`ship.title_format`). The description shows an AC × check table with `<details>` and no local links (enforced by `ship verify`). Reviewers need `gitlab_username`. New `ship plan --jira none|comment|transition` and `ship update-description`. A `## Quality` section lists the failing baseline tests.

- `visual` check crops the Figma png to the node box before comparing: the shadow/blur margin of an export (e.g. 480x800 png for a 448x768 node with a drop shadow) no longer counts as mismatch. Uses `absoluteBoundingBox` vs `absoluteRenderBounds` when the packed node has them, else the node `size` plus its `DROP_SHADOW`/`LAYER_BLUR` effects (png scale derived from the width; skipped when the height does not fit). The crop is written to `evidence/<CHK>/figma-cropped.png`. Unchanged when the sizes already match or bounds are missing (`factory/pngcrop.py`).
- `factory env up|check --run <epic child>`: a repo the child has no worktree for is resolved from the nearest dependency run (child `depends_on` and the parent's `epic.json`, BFS, transitive) that has one, so React can start/accept the API from the dependency's worktree. Other commands keep using the main checkout (`core.repo_path_for_env`).
- `gate build` commit checks (`commits_errors`) skip commits already reachable from a remote branch other than the run's own branch (inherited from other open MRs on epic branches); local-only commits and commits only on the run's own remote branch are still checked. One info line reports `N inherited commits on other remote branches skipped`. With no remotes the behaviour is unchanged.
- `visual` and `style` checks accept an optional `adapter` (run-relative JSON of `goto`/`click`/`fill`/`wait` actions) to reach UI states such as an open drawer. The collectors pass it as `--adapter` to `capture` and `style-probe`; the browser CLI now runs the adapter after load and before `--wait-for`/`--settle-ms` (and `style-probe` supports it). `gate plan` rejects `adapter` on other types or outside the run dir. URL-only checks are unchanged.
- Per-repo target branches: a workspace repo may set `target_branches: {"<target>": "<git branch>"}` (e.g. `pack` is `dev` in the API, `pack` in React). Targets stay logical in run.json, evidence ids and gates; `core.target_branch` translates them for `run branch`, `run mirror`, merge-base/baseline/repro, the build gate, the ship behind-count and the MR `target_branch` (`ship plan`, `ship verify`). `workspace check` validates the field. Unset keeps the old behaviour.
- Visual evidence on request (DESIGN §12). A run that touches UI (workspace repo `ui: true`, or with `ui` unset a repo whose env has a `login` block; a `ui` AC; browser/visual/style checks) fails `gate plan` until the user's answer is recorded with `factory run decide … --by user --user-said … --visual yes|no`. The skill asks it in the single question round: before/after screenshots of the fix for bugs, screenshots of the implemented screens for features. With yes: new check type `screenshot` (`path` capture, or a Playwright `spec` run with `--screenshot on`), one per touched UI repo. Bug runs capture `BEFORE-<check>` on the merge-base in `prove --repro --assume-env`. `gate reproduce` and `gate prove` (and so review and ship) require the images. `ship-plan.json` gets `visual_evidence` (before/after files per check), MR descriptions get a `## Visual evidence` table, and Gate S sends the images to the user. Browser CLI: `run-spec --screenshot on|only-on-failure|off`.

- `factory run delete <run...> --yes [--force]`: zips each run into `FACTORY_HOME/archive/runs/`, verifies the archive and only then removes the run folder. It refuses unfinished runs (only `done`/`report`/`blocked` without `--force`), a parent whose children are not deleted in the same call, and runs claimed by another session. Worktrees are listed, not removed. Workers cannot run it (`worker-guard.js` also blocks `run claim`).

- Parallel sessions (DESIGN §11). Workspace `orchestration: {sessions, per}` lets a batch run one visible host session per ticket. The parent coordinates with `factory batch status`, and children claim their runs (`factory run claim [--takeover]`). Skill: `references/sessions.md`, plus Progress and Worker-questions rules (every phase is narrated; a worker assumption that reduces proof reaches the user).
- Env lease. Workspace `env: {lease, lease_ttl_s}` adds `factory env lease acquire|release|status`: a FIFO queue for the one local env. `env up|login --run` need the lease, `env down` refuses a non-owner unless `--force`, and `prove`/`env check` renew the heartbeat. `up` is atomic under a lock file.
- Safe run writes. `run.json` carries a `rev` counter, a per-run lock is held while saving, and a concurrent change is refused instead of lost. `run_update` is used for the short mutators, and `write_json` uses unique temp files and retries on Windows sharing errors.
- `factory run log <run>` prints a run's event timeline. `metrics` attributes child-session transcripts to the parent.
- Quality delta: absolute worktree paths are scrubbed from failure ids, so typecheck errors in the baseline worktree no longer count as new in the run worktree.

- dev.mcp `save_to` integration: gates and commands that miss a remote file (`gate intake|plan`, `figma check`, `ship verify`, `feedback ingest`, `review start|queue`) print the exact dev.mcp call with an absolute, forward-slash `save_to` and `overwrite=true` (`FETCH ...` lines; `fetch: [{tool, args}]` with `--json`; `<fileKey>`/`<iid>` placeholders when unknown). Skill, references, and agents now say "call the tool with `save_to`" instead of writing responses by hand.
- Pack and readback readers accept the raw tool output: `figma/meta-<fileKey>.json` per file, `{merge_request: ...}` readbacks, MR notes plus `pipeline-<repo>-<target>-jobs.json` for feedback.
- `protect.js` denies any `mcp__*` call whose `save_to` targets `run.json`, `metrics.json`, `ship-plan.json`, `review-report.json|md`, `evidence/`, `reviews/`, `baseline/`; `review-report.json|md` are now protected for file tools and shell too. The installed matcher adds `mcp__.*`.
- `install.py --mcp-config`: merges `DEV_MCP_SAVE_ROOTS`, `DEV_MCP_SAVE_ALLOW_DOT`, `DEV_MCP_SPILL_KB` into the `dev.mcp` server `env` (missing keys only, backup first, `--dry-run` diff).

- Review runs (DESIGN §7): `review queue|start|report|fix`, `run branch --mr` (detached worktree at the MR head), `kind: review` / `review-batch` phase machines (intake, plan, prove, review, report, done; no build or ship), `review-report.json` and `.md` with a verdict per MR (`ok`, `not-ok`, `incomplete`). Nothing is posted remotely without the user's approval. Skill: `references/review.md` and a short section in `SKILL.md`.
- Hooks hardening (defence in depth; the CLI's evidence digests and plan-lock hashes stay authoritative): shell/PowerShell commands that mention a run path (any slash style, `$env:FACTORY_HOME`, `%FACTORY_HOME%`, `$FACTORY_HOME`, `~`) together with any write-capable verb are denied (`[IO.File]::WriteAllText`, `curl -o`, `-OutFile`, `tar`, `Expand-Archive`, `certutil`, ...); `python -`/`-c`/`<file>.py` and `node -e`/`-` that reference FACTORY_HOME or `.factory` are denied unless the command is the factory CLI; workers cannot use `-EncodedCommand`. `runs/*/acs.json`, `diagnosis.md`, `checks/**`, `figma/**` are protected from shell writes, MCP `save_to` (except into `figma/`) and, via worker-guard, from builder/auditor/scout (author only). Setting `FACTORY_ROLE` from a command is denied in every session; `FACTORY_ROLE=auditor` only for the auditor.
- `install.py`: secret-looking values are masked (`***`) in printed diffs; settings.json, CLAUDE.md, existing factory agents, skills/factory and hooks are backed up to `<profile>/backups/factory-<timestamp>/` first; a running Claude app blocks editing `.claude.json` unless `--yes`; a missing default `<profile>/.claude.json` is skipped with a note (exit 0); a PowerShell `SetEnvironmentVariable` PATH hint is printed (never executed, no `setx`).
