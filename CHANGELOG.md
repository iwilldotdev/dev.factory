## Unreleased

- feat: hotfix base target serves a dependency without a run worktree from `target_paths[<base>]`. Motivated by a hotfix workspace whose dependency repos keep a second checkout on the base branch: when the hotfix touched only the dependent repo, its dependency (no run worktree) was served from the repo's main `path`, on whatever branch it was. Now, in a hotfix run, for the base target (no `--target`, or the base) a repo without a run worktree and with `target_paths[<base>]` is served from that directory; a repo with a run worktree always keeps it, mirror targets and non-hotfix runs are unchanged. New `core.repo_serve_path` (`target_serve_path`, else `repo_path_for_env`) is the single resolution used by `env up|check|down|login`, restarts and `--auto-restart`, the stale comparison, `env.seed`, the repro temporary worktree and (through `target_serve_path`) `prove`'s `dep_binding`, so the served path is the expected one. `workspace check` now accepts a base key (unknown targets, non-string and relative paths are still rejected; still no filesystem check). Tests: `tests/test_target_paths_base.py`, `tests/test_env_mirror_target.py`.

- fix: protect hook narrows the provably-safe grammar. Motivated by a fourth independent audit of the hook, which executed its probes against a fake factory tree and found four families of real writes the grammar let through: (R1) Git Bash's `/proc/cygdrive/c/...` alias of the drive as the target of `rm`/`cp`/`mv`/`sed -i`/`touch` or after a `cd` (the mount table was guessed, not known); (R2) PowerShell 5.1 re-quoting a native argument with spaces without escaping its inner quotes (`sed s/a/b/ 'q "q -i" q' <run>/run.json` reaches sed with `-i`; `python -c` code whose inner quotes are stripped runs its "data"); (R3) `mv` of a folder holding a junction into the run before a `cp` through it (the real path was checked before the move); (R4) `git -C <repo> checkout` where the repository's `core.worktree` is the run folder. The decision keeps its shape (`extra || ((baseline || coarse) && !provablySafe)`); the grammar now accepts only: readers (with listed flags for `sort`/`diff`/`gzip -c`) and their output redirections; `cp` with listed flags (no `-L`, `-p`, which PowerShell's Copy-Item binds to `-LiteralPath`/`-PipelineVariable`; no comma) and two operands or more; `sed [-i|-n|-E|-r] s/a/b/[gI0-9]`; `cd` with one absolute literal; the factory CLI (arguments are data but hold none of `"&|<>^%!`, which cmd.exe reads in `factory.cmd` arguments). `rm`, `rmdir`, `mkdir`, `touch`, `mv`, `rsync`, `git` and `python -c` are out and keep the baseline verdict. A quoted word outside factory segments is not empty, holds no whitespace or quote and does not start with `-`. A write target is judged positively: `/dev/null`/`NUL`, or a strict ASCII literal whose real path (every candidate cwd, every shell reading) lies inside a safe root (the real temp dir; the real session cwd when it is outside every factory home), neither inside nor above a factory home (so never `<run>/remote` or `notes`), not an existing folder, not a hard-linked file; on Windows only `/<drive>/` and `/tmp` are mapped and `/tmp` is also `C:\tmp` to PowerShell, so it is no safe root; a write at or under an earlier `cp` destination of the same command is refused. Known false positives that stay denied (use separate commands or the Edit/Write tools): `git` in another repository with a run-path read, `python -c` reading a run file, `rm`/`mv`/`mkdir`/`touch`/`rsync` of scratch files in a command that also reads a run path, PowerShell copiers, `<run>/remote` or `notes` as a write target, a `cp` into an existing folder, a quoted word with a space, `/tmp/...` targets on Windows. Not fixed here (allowed before the grammar too): editors, `perl -pi` and redirections into the `/proc/cygdrive` spelling, and a lone `factory.cmd` segment whose quoted data holds cmd.exe metacharacters. Differential against the frozen baseline: own corpus 22625 commands (20070 baseline denials; gains copy-out 525, heredoc-data 2), audit corpus 6326 with the fourth audit's generators (5467 baseline denials; gains copy-out 7, gzip-to-stdout 3), 0 unexplained. Tests: `claude/hooks/test/guard-provable.test.mjs` (rules for re-quoting, factory data, cp flags, safe roots, mounts, junction/TOCTOU/hard-link probes on disk, a still-denied table, end-to-end R1–R4 rows), `claude/hooks/test/guard-regressions.test.mjs` (R1–R4 and minors in the regression table, still-denied table, narrowed gain classes), `claude/hooks/test/guard-targets.test.mjs`, `claude/hooks/test/fixtures/audit-corpus.cjs` (`probes5`).

- fix: protect hook lifts a coarse denial only for provably safe commands. Motivated by a third independent audit of the hook (6069 generated probes against the frozen pre-target-rule baseline): about 157 real writes that the baseline denied were allowed, in seven families — a verb hidden behind a function, alias or `set --` defined in another segment (`zap() { rm -rf "$1"; }; zap <run>/evidence`, `Set-Alias wipe Clear-Content`), `xargs -I` completing the protected name, a junction alias of the profile (`C:/Documents and Settings/<user>/...`), bash escapes in all-backslash paths (`run.jso\n`), odd spellings attached to a flag value (`dd of=//localhost/c$/...`, `cp -t//127.0.0.1/...`, `-Destination:\\localhost\...`, `of=~<user>/...`), cmd.exe carets and quote loss, and `Push-Location`. Fail fast and recovery (DESIGN §13), driven by the findings of real runs since 13/11 (Handoffs/ and run transcripts):

- prove: per-check wall-clock caps (`timeout_s`, `limits.check_timeout_s`, 120 s UI / 60 s api) kill the process tree. An env-kind failure skips the repo's remaining runtime checks and exits 3. Two identical failures stop the batch. New `PROVE-FAIL`/`ENV-FAIL` lines. A stale env is restarted once. prove no longer overwrites run.json (`run_update`). `--check` accepts `QUALITY-*` and `RULE-*`.
- Browser CLI: `--timeout-ms`, `--goto-timeout-ms` (30 s) and `--wait-until` (`load`), so there are no more 360 s test or 180 s networkidle waits.
- env check is a preflight: repo and run come from the cwd, a status below 500 is healthy (redirects are not followed), exit codes 0/1/2/3/4, `--auto-restart`. HTTP.sys (PID 4) is judged by health. The lease heartbeat runs before every check, a live holder pid keeps the lease, and `lease release` stops the run's envs. Factory only kills processes whose create time matches its own record.
- Workers: a blocked contract (one self-repair, then `status: blocked` with `infra_signal`, `first_seen_at`, `tried`), enforced by the new `failfast.js` hook on author, builder and auditor. `factory wait` replaces `sleep`, which workers cannot use. Guards allow read-only commands and scripts on run files. `runs/_inbox/**` is writable by scouts. At plan, new browser and api checks get a dry run. The orchestrator runs `env check` before delegating.
- Gates and runs: `review fix` records the MR head and `gate build` checks only later commits, with inherited commits limited to known branches. New `run verify-human` for user-confirmed human checks; pending human checks do not count as review loops. A checks-only replan keeps the code review. Generated files under `checks/` are left out of the plan lock, and adapter files are locked. New `run close` (phase `closed`), `run list --all`, `run retype`, a bug type derived from the Jira issuetype, hotfix mirror branch names that cannot collide, blocker kind `decision`, `workspace list|show`, and `orchestration.max_parallel`. `repo_path_for_env` warns when it falls back to the main checkout.
- Collectors: dotnet output is forced to English. A test or red-green check that runs zero tests fails as `setup`.
- Ship: the MR title is `[KEY] - summary` (`ship.title_format`). The description shows an AC × check table with `<details>` and no local links (enforced by `ship verify`). Reviewers need `gitlab_username`. New `ship plan --jira none|comment|transition` and `ship update-description`. A `## Quality` section lists the failing baseline tests.

- `visual` check crops the Figma png to the node box before comparing: the shadow/blur margin of an export (e.g. 480x800 png for a 448x768 node with a drop shadow) no longer counts as mismatch. Uses `absoluteBoundingBox` vs `absoluteRenderBounds` when the packed node has them, else the node `size` plus its `DROP_SHADOW`/`LAYER_BLUR` effects (png scale derived from the width; skipped when the height does not fit). The crop is written to `evidence/<CHK>/figma-cropped.png`. Unchanged when the sizes already match or bounds are missing (`factory/pngcrop.py`).
- `factory env up|check --run <epic child>`: a repo the child has no worktree for is resolved from the nearest dependency run (child `depends_on` and the parent's `epic.json`, BFS, transitive) that has one, so React can start/accept the API from the dependency's worktree. Other commands keep using the main checkout (`core.repo_path_for_env`).
- `gate build` commit checks (`commits_errors`) skip commits already reachable from a remote branch other than the run's own branch (inherited from other open MRs on epic branches); local-only commits and commits only on the run's own remote branch are still checked. One info line reports `N inherited commits on other remote branches skipped`. With no remotes the behaviour is unchanged.
- `visual` and `style` checks accept an optional `adapter` (run-relative JSON of `goto`/`click`/`fill`/`wait` actions) to reach UI states such as an open drawer. The collectors pass it as `--adapter` to `capture` and `style-probe`; the browser CLI now runs the adapter after load and before `--wait-for`/`--settle-ms` (and `style-probe` supports it). `gate plan` rejects `adapter` on other types or outside the run dir. URL-only checks are unchanged.

Worktrees are listed, not removed. Workers cannot run it (`worker-guard.js` also blocks `run claim`).

- Env lease. - Safe run writes. `run.json` carries a `rev` counter, a per-run lock is held while saving, and a concurrent change is refused instead of lost. `run_update` is used for the short mutators, and `write_json` uses unique temp files and retries on Windows sharing errors.
